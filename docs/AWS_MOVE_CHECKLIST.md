# מה נשאר כדי לעבור ל-AWS

> **המצב ב-2026-10-12:** הכול מוכן בקוד, ושום דבר לא הוקם ב-AWS. אין חשבון AWS, ולפי ההחלטה שלך לא
> פותחים עכשיו. המסמך הזה הוא הרשימה של מה שנשאר ליום שתחליט לעבור, לפי הסדר.
>
> **ההחלטות שכבר התקבלו:** מבנה **A** (מנוהל, Ollama על CPU), אזור תל אביב (`il-central-1`), נשארים עם
> Ollama. עלות משוערת: **כ-325$ לחודש** ([AWS_COST_ESTIMATE.md](AWS_COST_ESTIMATE.md)).

## 3. מה נשאר — דברים שאני עושה אחרי האישור

### שלב א: הכנה על המחשב הנוכחי (אפשר כבר היום, כ-10 דקות, דורש הפעלה מחדש)
המערכת היום מצפינה את חיבורי Google עם מפתח הכניסה לדשבורד, ואין לה מפתח גיבוי. ב-AWS אלה שני
מפתחות נפרדים, והם כבר נוצרו בתיקיית `keys/`. לפני המעבר המחשב הנוכחי צריך לעבור אליהם:
```bash
python -m zenflow.keys adopt               # מוסיף ל-.env את שני המפתחות מהתיקייה, בלי להציג אותם
python -m zenflow.rotate_token_key --dry-run
python -m zenflow.rotate_token_key         # מגבה, ואז מצפין מחדש את חיבורי Google
```
אחרי זה מפעילים את המערכת מחדש. מאותו רגע הגיבויים האוטומטיים מוצפנים.

### שלב ב: הקמה (כשעה עד שעתיים)
1. מאגר למצב של Terraform (פקודות ב-[INFRA.md](INFRA.md)).
2. למלא שלושה ערכים ב-`infra/terraform/envs/prod.tfvars`: הדומיין, מזהה ה-Hosted Zone, המייל.
3. `terraform plan`. **אתה קורא את התוכנית ומאשר**, ורק אז `terraform apply`.
4. להעלות את שלושת הקונטיינרים.
5. למלא את הסודות: `python -m zenflow.keys app-secret` מכין קובץ אחד מוכן להעלאה, בלי להציג ערכים.
6. להריץ את בניית מסד הנתונים (משימת `migrate`).

### שלב ג: בדיקה על סביבת ניסיון (יום אחד, כ-11$)
1. להקים `staging` מאותו קוד, עם נתונים מדומים.
2. למדוד כמה זמן לוקח ל-Ollama על CPU לענות. אם זה איטי מדי, זה הרגע להחליט על שרת חזק יותר.
3. חזרה מלאה על תהליך המעבר, ותרגיל שחזור מגיבוי של RDS.
4. למחוק את `staging`.

### שלב ד: המעבר עצמו (כ-30 דקות השבתה, בשעה שקטה)
לפי [MIGRATION_RUNBOOK.md](MIGRATION_RUNBOOK.md): עוצרים את המחשב הנוכחי, גיבוי אחרון מוצפן, העברת
הנתונים עם אימות, הפעלת השירותים (הבוטים עוברים לבד ל-AWS), ורשימת בדיקה של 10 דקות. אם משהו
נכשל ולא נפתר ב-15 דקות, חוזרים לאחור: המחשב הנוכחי נשאר שלם.

### שלב ה: אחרי המעבר
- לשמור את המחשב הנוכחי ואת הגיבוי שלו 30 יום בלי לגעת.
- לוודא שהתראת התקציב (400$) והתראות התקלות מגיעות למייל.
- אחת לרבעון: תרגיל שחזור.

## 4. מה עלול להפתיע

| מה | למה | מה עושים |
|---|---|---|
| חשבון חדש מוגבל במכסות | AWS עשוי להגביל חשבון חדש במספר השרתים | לבדוק את המכסות אחרי פתיחת החשבון, ולבקש הגדלה מראש אם צריך |
| תעודת האבטחה מתעכבת | אימות הדומיין תלוי ב-DNS | בדרך כלל דקות. לפעמים שעה |
| Ollama על CPU איטי | בלי כרטיס מסך תשובה לוקחת יותר זמן | נמדד בשלב ג. שדרוג ל-`c7i.2xlarge` מוסיף כ-147$ לחודש |
| חיבורי Google לא עובדים אחרי המעבר | מפתח ההצפנה לא זהה | שלב א פותר את זה מראש |
| הבוט לא עונה אחרי המעבר | שני עותקים רצים | עוצרים את המחשב הישן לפני שמפעילים את החדש |
